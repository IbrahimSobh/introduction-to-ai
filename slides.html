Part A builds the vocabulary. Part B is the main focus: how LLMs work and how to build useful, safe systems with them.

AI is a family of nested ideas

  • Artificial intelligence: machines doing tasks we link to human intelligence (including hand-written rules)
  • Machine learning: learns patterns from data instead of following hand-written rules
  • Deep learning: neural networks with many layers
  • Generative AI: creates new text, images, code
Generative AI is the innermost circle: today's chatbots are still machine learning, learning patterns from data.
Teaching a child to recognise cats: you don't list rules about whiskers and ears, you show many pictures and say "cat" or "not cat". Machine learning works the same way.

Machines learn in three ways

TypeLearns fromExample
Supervisedexamples with the right answers (labels)emails marked spam / not spam → classify new emails
Unsupervisedexamples without answerscustomer data → discover groups of similar customers
Reinforcementtrial and error, with rewards and penaltiesa game player learns which moves lead to a win
The data decides the method: labels → supervised, no labels → unsupervised, rewards → reinforcement.
Clustering is the most common unsupervised method: the groups come from the data, not from labels. A shop groups customers by behaviour, then treats each group differently (win-back discounts, deals for bargain hunters, early access for big spenders). Nobody labelled the customers first. Reinforcement learning is also part of how chat assistants are tuned (slide 10).

Supervised learning answers "Which one?" or "How much?"

ClassificationRegression
Predictsa category from a fixed lista number that can take any value (continuous)
Asks"Which one?""How much?" or "Where?"
Examplespam or not spama house price
Real systems often do both at once. A car camera says what each object is (classification) and where it is (regression).
The car learns from thousands of road images where people drew the boxes and wrote the labels, so this is supervised learning. It needs both answers to decide whether to slow down.

A model is a formula, and training finds its parameters

  • The simplest model is a straight line: y = a·x + b (x = house size, y = price)
  • Model: the shape we assume (here, a line)
  • Parameters: the numbers that set its exact shape (a = slope, b = starting height)
  • Training: find the a and b that make the line fit the data best
  • Prediction: put a new size into the trained formula to get a price
Training is iterative: many small steps, each nudging the parameters to reduce the error.
A real-estate agent who has seen hundreds of sales can guess a price from the size. A model learns the same relation from data and uses it on houses it has never seen. Because a price is a number, this is regression.

A good model works on data it hasn't seen

Keep a test set aside that the model never sees during training, so it can be checked honestly.

Training errorTest errorWhat's happening
Underfittinghighhightoo simple to capture the pattern
Good fitlowlowlearned the real pattern, generalises
Overfittingvery lowhighmemorised the training data, noise included

Remedies: more and better data, simpler models, test on held-out data. Garbage in, garbage out: bad or unrepresentative data teaches the wrong pattern.

Low training error alone proves nothing. Only performance on unseen data counts.
Overfitting is like memorising last year's exam answers: perfect on those questions, lost on new ones. Complexity means the number of parameters. More parameters can fit the real pattern, or the noise. Data-quality work is often most of the effort in real AI projects.

A neural network learns by nudging its weights

  • Neurons in layers: input → hidden → output
  • Each connection has a weight: how much one neuron's output matters to the next
  • An activation function bends each result, so the network can learn curves
  • Repeat many times: forward pass → measure the error → backpropagation (who caused it) → update every weight a little (gradient descent)
Same idea as the line, just bigger: a line has 2 parameters, the small network 13, an LLM billions, which is why training needs many GPUs.
A team passes a decision along and learns whom to trust: bigger weights mean more trust. Gradient descent is like walking down a hill in thick fog: you feel the slope under your feet and step downhill, again and again. The demo task is XOR (the light is on when exactly one switch is on), which no straight line can solve. That's why it needs a hidden layer. Deep learning means many layers. Training that many parameters takes huge numbers of parallel calculations, which is why it needs many GPUs.

The main part of the talk: how LLMs work, and how to build useful, safe systems with them.

An LLM is a very well-read autocomplete

  • Generative AI creates new content: text, code, images, audio, video
  • A large language model (LLM) is a very large neural network trained on huge amounts of text to predict what comes next
  • Same idea as the line: a model with learned parameters, only billions of them
  • Many models are multimodal: they also read images, audio and documents
An LLM's core skill is predicting the next piece of text. Answering, writing and coding all emerge from doing that at huge scale.
The rest of the course focuses on text and LLMs, because most AI tools at work are built on them.

LLMs read tokens, and the context window is their working memory

  • Token: a common chunk of text, such as learn + ing. In English, 1 token ≈ 4 characters ≈ ¾ of a word
  • Context window: the most tokens the model can handle at once: prompt, conversation, documents and the answer
  • 128K tokens ≈ a 300-page book
  • When it fills up, the earliest messages are dropped or summarised, so the model "forgets"
  • Tokens are how AI use is measured and billed
The model only works with what fits in its context window.

Pre-training gives knowledge, tuning makes it an assistant

  1. Pre-training: predict the next token across a huge amount of text → a base model that just continues text
  2. Instruction tuning: learn from instructions paired with good answers → acts as an assistant
  3. Preference tuning (e.g. RLHF): people rate answers → more helpful, honest and safe
You type: "What is the capital of France?"
Base model"What is the capital of Germany? What is the capital of Italy?…"
Instruction-tuned"The capital of France is Paris."
Pre-training gives the model its knowledge. Tuning shapes how it behaves.
RLHF = reinforcement learning from human feedback, the third way of learning from slide 3. Pre-training runs trillions of next-token predictions.

Attention lets every word look at every other word

  • Most LLMs use the Transformer design (2017). Its key idea is attention
  • For each token, the model scores how relevant every other token is, then mixes in meaning from the most relevant ones
  • This happens in every layer, with many attention heads
  • text → tokens → embeddings → Transformer layers (× many) → next-token probabilities
Attention lets each token use information from anywhere in the context, all in parallel. That parallel work suits GPUs and made today's very large models possible.
Attention is the model's highlighter: for each word, it highlights the other words that help explain it. The weights in the picture are set by hand to show the idea; a real model learns them. Each attention head looks for a different kind of link.

An LLM writes one likely token at a time

  • At each step: give every possible next token a probability → pick one → add it → repeat
  • The pick is random but weighted, so the same prompt can give different answers
TemperatureBehaviourUse it for
Low (0–0.3)consistent, most likelyfacts, code, extraction
Medium (0.5–0.8)balancedchat, explanations, emails
High (≥ 1)varied, can driftbrainstorming, stories
Fluent is not the same as true. The model picks likely-sounding tokens, and that's the root of hallucinations.
Temperature sets how adventurous the pick is. Low temperature is the careful friend who always picks the obvious word; high temperature is the adventurous one. Chat apps set the temperature for you; developers choose it when building apps.

Ask clearly and get reliable results

Six things to add to a prompt:

TechniqueWhat you add
Clear instructionexactly what to do, the options, length, audience
Role"You are a…" (often in the system prompt)
Contextbackground, goal, constraints
Examples (few-shot)a few input → output pairs
Step by step"think step by step", or list the steps
Structured outputtable / list / JSON with keys
Treat prompts like code: test them on real inputs, change one thing at a time, and keep the versions that work.
It's like briefing a smart new colleague who knows a lot but nothing about your situation. Why each one helps: a clear instruction avoids "vague in, vague out"; a role sets expertise and tone; context tells the model your situation, which it can't know; examples show the exact labels and format; step by step gives better reasoning that is easy to check; structured output is easy to read and to use in programs.

The model only knows what's in its context

Context engineering means deciding everything that goes into the context window for each request: instructions, the right documents, tool definitions and results, memories, chat history, and what to leave out or summarise.

Prompt engineeringContext engineering
Focushow you write the requestwhat the model sees when it answers
Done bya person, once per taskthe app or agent harness, at every step
A great prompt with the wrong documents still gives a wrong answer, and too much irrelevant text buries the important part.
Writing a clear brief, and also packing the right folder of papers to go with it, and nothing extra. RAG and agents (next slides) are context engineering in action.

Embeddings turn meaning into numbers

  • An embedding is a list of numbers (a vector) that captures a text's meaning
  • Similar meaning → vectors that point the same way, even with no shared words: "cheap flights" ≈ "low-cost airfares"
  • Cosine similarity measures this: 1 = same meaning, 0 = unrelated
  • Documents are split into chunks; each is embedded and stored in a vector database. Too big wastes context; too small loses meaning
Search by meaning, not by keywords: this is how RAG finds the right passages (next slide).
Real embeddings have hundreds or thousands of numbers. The demo uses 3 so you can see them. Chunks are a few paragraphs, with a little overlap.

RAG: retrieve, augment, generate

Why LLMs need outside knowledge:

  • Old: they only know their training data, up to a cut-off date
  • Private: they have never seen your policies, contracts or databases
  • Trust: answers from retrieved sources can cite them, which reduces hallucinations
RAG keeps knowledge outside the model. To update it, change the documents and re-index them. No retraining needed.
An open-book exam: the student (the LLM) is clever but doesn't know your company handbook. A librarian finds the right pages and puts them on the desk. Example: "How many vacation days do I get?" The retrieve step uses embedding similarity from the previous slide.

Agent = LLM + harness

The LLM is the brain: it reads, reasons and decides, but on its own it only turns text into text. The harness is the program around it:

Harness jobWhat it means
Toolsoffers tools and runs the ones the model asks for
The loopsends the conversation back until done or a limit is hit
Context and memorydecides what goes in the window; saves and recalls memories
Safetypermissions and limits; a person approves risky actions
The model never runs anything itself, it only asks. That's why safety checks belong in the harness. Same LLM, different harness = a different agent.
Tool calling: the model replies with a tool name and arguments, e.g. get_weather({"city": "Paris"}); the harness runs it and sends back the result (the diagram shows this). A chatbot is a knowledgeable friend on the phone who can only talk. An agent is an assistant at a desk with a computer and a phone. The harness is the desk, the computer, the to-do list and the office rules.

Agents loop: think, act, observe

  • The agent plans, then repeats think → act → observe, adjusting the plan, until done or a limit is hit (the ReAct pattern)
  • Memory: short-term = the context window; long-term = stored outside the model, fetched when relevant
You needUse
an answer from general knowledgeplain chat
answers from your own documentsRAG
several steps or real actionsan agent
Agents are slower and cost more, so use the simplest option that does the job.
Short-term memory lives in the context window and is gone when the session ends (the forecast it just looked up). Long-term memory lives outside the model, in a database, files or a vector DB, and is fetched when relevant ("home city: Paris").

MCP gives access, Skills give know-how

  • MCP (Model Context Protocol): an open standard for connecting AI apps to tools and data. Build a connector once, use it in any app that supports MCP
  • An app (the host) talks through clients to servers, each in front of one system. Servers offer tools, resources (data) and prompts
  • Skills: folders with a SKILL.md of instructions, plus optional scripts and templates
  • The agent sees only each skill's short description, and loads the full instructions when a task matches
Together: the skill says what to gather and how to present it, and MCP tools fetch the data.
For a new employee, MCP is their keys and logins; Skills are the team's how-to guides. MCP is like a USB-C port for AI. Anthropic introduced it in late 2024, and many tools now support it. Example: "Write release notes for v2.0" → release-notes skill → GitHub list_merged_prs → formatted notes.

Start with prompts, add RAG, fine-tune last

Fine-tuning trains a pre-trained model further on your own examples. It changes the model's weights; prompting and RAG only change its input.

PromptingRAGFine-tuning
Changesthe instructionsthe information in the promptthe model's weights
Best formost tasks: start hereup-to-date or private knowledgeconsistent style, format, narrow tasks
Effortlowmediumhigher
Updatingedit the promptupdate the documentstrain again
Start with prompts. Add RAG for missing knowledge. Fine-tune for behaviour prompts can't reliably produce. The approaches also combine.
A doctor who finishes medical school (pre-training) and then specialises (fine-tuning). Fine-tuning can make a small, cheap model match a big one on one task. Efficient methods such as LoRA update only a small part of the model. Examples: sorting support tickets into your own categories; a brand's writing style. Fine-tuning effort: collect data, train, evaluate.

Four risks every AI user must know

RiskWhat it isHow to reduce it
Hallucinationsconfident, fluent answers that are false (fake facts, quotes, sources)ground with RAG, ask for citations, verify important facts
Biasrepeats unfair patterns from human datacheck results across groups, balanced data, a person checks decisions about people
Privacysensitive data in prompts may be stored, seen or leakedfollow your organisation's rules, use approved tools, remove personal and secret data
Prompt injectionhidden instructions in content the AI reads try to take controltreat outside content as data, minimal tool permissions, approval for risky actions
AI is a very fast, very confident trainee: great for drafts, but someone checks before anything important goes out.

Prompt injection needs layered defences, and a human in the loop

An agent can't always tell your instructions from instructions hidden in a web page, email or file. No single fix exists, so layer the defences:

  1. Treat outside content as data, not instructions
  2. Least privilege: only the tools the task needs
  3. Human approval before sending or acting

Keep a human in the loop when stakes are high, actions are hard to undo, or facts are hard to check.

There is no perfect fix for prompt injection yet. Defence comes in layers, and the last layer is a person.
When to keep a human in the loop: high stakes (medical, legal, financial, safety, decisions about people); actions that are hard to undo (sending, paying, deleting, publishing); facts that are hard to check (numbers, quotes, names, sources); questions outside the model's knowledge (recent events, private data without RAG).

Key takeaways

  1. ML learns patterns from data instead of rules written by hand.
  2. A model is a formula, and training tunes its parameters. Judge it on data it hasn't seen.
  3. Neural networks are the same idea with billions of parameters.
  4. An LLM predicts the next token. Fluent is not the same as true.
  5. Clear prompts and the right context make results reliable.
  6. RAG answers from your documents, with sources.
  7. Agent = LLM + harness. The model asks; the harness acts.
  8. MCP gives access; Skills give know-how.
  9. Prompt first, then RAG, then fine-tune.
  10. Know the risks, and keep a human in the loop for anything that matters.
